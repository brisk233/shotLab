# 动态篮筐自动校准

日期：2026-11-24

## 问题

手持跟拍视频中，篮筐会随镜头横移、上下漂移并短暂离镜。固定首帧筐框会让命中判定、
投篮类型和 ROI 全部偏离。

样例视频 `c61ea74f8e38ad6e54560c565b332ae0.mp4` 为 `720 x 1280 / 30fps / 15.4s`，
篮筐中心在画面右侧持续移动，不能使用固定框。

## 实现

1. `RimCandidateFinder` 在上半画面提取横向橙色候选，并结合：
   - 横向环宽高比
   - 篮板上方白色低饱和上下文
   - 局部边缘密度
   - 候选面积和画面位置
2. `DynamicRimCalibrator` 使用速度预测进行逐帧数据关联：
   - 平滑移动持续更新
   - 单帧远跳拒绝
   - 800ms 内漏检用预测位置补间
   - 硬切时清空旧状态并重新捕获
   - 超过补间窗口后允许全新位置重生
3. `ShotAnalyzer` 每两帧运行一次候选提取，逐帧写入 `RimTrackPoint`。
4. `TrackletEngine` 的峰值过滤使用最高点时刻筐框，穿筐使用交点时刻筐框，
   投篮类型使用出手时刻筐框；固定筐本地修正也只使用当前镜头段。
5. 首次选择视频时先自动找筐；成功直接分析，失败仍进入原人工校准流程。
6. 场景切镜使用更高差异阈值并做 500ms 去抖；切镜会递增 `segment`，
   轨迹拼接、固定筐本地回退和 1.05 秒去重都不能跨段执行。单帧可疑切镜
   不直接重置筐轨迹，持续失配超过 800ms 后才重新捕获。
7. `ColorBallCandidateFinder` 用砖红/橙色连通域补充 YOLO 在高空飞行段的漏检，
   同时抑制静止球架和与篮筐重叠的大块橙色区域。
8. `TrackletEngine` 必须看到明显上升或开局已在空中才接受动态筐出手。
   有实测穿筐结论时以实测为准，球撞筐/撞回球网后反弹不得被局部外推改判命中；
   回程本身也不生成新出手。
9. 人工确认或机位记忆的首帧筐框按固定机位处理，不再被动态候选替换；
   同时禁用全局/局部轨迹自校正和橙色飞行补点，确保固定筐不会被伪轨迹反向带偏。
   自动找筐路径才启用动态筐跟踪；动态关联使用更紧的横向门限，重捕不得
   小于首帧筐宽的 55%，避免鞋、广告牌等橙色干扰物逐步接管真实篮筐。

## 回归

- 纯状态机：平滑运动、短时补间、远跳拒绝、切镜重建、长时丢检再捕获、尺寸平滑。
- 合成像素：横向篮筐优先于橙色地板、竖直干扰和青蓝广告牌。
- 真实视频：16 帧样例连续跟踪，中心和误差受控。
- 投篮链路：移动筐、竖直移动筐、预测交点、切镜隔离和跨镜头连续出手去重。
- 真机 15.5 秒样例：纯自动路径 `3投1中`，出手时间约 `0.0s / 6.0s / 12.1s`。
- 真机出手明细：第 2、3 次单球预览均可成功切片并播放。
- HEVC 单球预览从首个视频关键帧开始，按段内锚点平移原始 B 帧 PTS；
  实测第 2、3 段所有帧间隔稳定在约 `33.333ms`，无时间轴压缩或跳帧。

## 诊断

`tracklet_dump.json` 新增：

```json
{
  "rimTrack": [
    {
      "tMs": 0,
      "rim": [0.714, 0.413, 0.753, 0.434],
      "confidence": 0.58,
      "segment": 0
    }
  ],
  "frames": [
    {
      "t": 0.0,
      "segment": 0
    }
  ]
}
```

`rim` 仍表示输入粗框，`correctedRim` 表示最终框，`rimTrack` 保存逐帧动态轨迹。
事件记录也带 `segment`，供 PC 复算保持与 Android 相同的跨镜头规则。
